ALTER EGO — Supabase email template (guest → email)

1) Dashboard → Authentication → Email Templates → open "Change email address"

2) Subject (suggested):
   Confirm your ALTER EGO email

3) Body: paste the full contents of change-email-address.html into the template editor.

4) Authentication → URL Configuration
   - Site URL: your production app URL or Expo dev URL you use for testing.
   - Redirect URLs: add every URL the app uses after auth, including:
     - alter-ego:// (Expo scheme from app.json)
     - exp://127.0.0.1:8081 and exp://YOUR_LAN_IP:8081 (Expo Go / dev)
     - http://localhost:3000 (if you use web redirects during dev)

   The mobile app now passes emailRedirectTo (Expo deep link) when upgrading from guest; that URL must be in the allow list or the confirmation link will fail or open the wrong place.

5) Why the old email looked broken
   Supabase leaves {{ .Email }} empty for anonymous → email. The default template assumed both old and new emails existed. The custom template uses {{ if .Email }} ... {{ else }} ... for first-time linking.

6) Why the link looked missing
   Some default snippets use plain text instead of <a href="{{ .ConfirmationURL }}">. This template includes a real button link plus a fallback plain URL.

7) Localhost
   Email links point to your Supabase project (e.g. https://YOUR_REF.supabase.co/auth/v1/verify?...). That always works. The redirect_to in the link must match your allow list so after verifying, the browser/app can return to your app. For pure localhost without a matching redirect URL, add the exact redirect you pass from the app (see makeRedirectUri / Expo).
